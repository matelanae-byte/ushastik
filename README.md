# AI Transcriber

Локальная расшифровка аудио и видео с таймкодами. Приложение создано на основе «Ушастика» Валерия Курземнека.

Windows 11 x64 — основная цель для сборки. Windows 10 x64 учитывается при выборе зависимостей. Для macOS сохранён нативный сценарий сборки. Совместимость этой версии на Windows и macOS требует отдельной проверки. Сведения о прежних дистрибутивах доступны в [заметках о выпуске Ушастика 0.3.1](docs/RELEASE-v0.3.1.md).

## Что умеет

| Режим | Когда выбрать |
| --- | --- |
| **По голосам** | Обычная запись разговора. Приложение определит участников по голосам; для звонка двух человек удобно оставить «Участников: 2». |
| **Два канала** | Стереозапись, в которой каждый собеседник записан в отдельный канал. |
| **Общий текст** | Нужна расшифровка без определения участников. |

Добавляйте несколько записей, целую папку или перетаскивайте файлы в окно. AI Transcriber обрабатывает очередь последовательно и сохраняет **TXT, SRT, JSON и Word (DOCX)**. Готовый разговор можно прочитать в приложении, скопировать и переименовать участников: например, «Менеджер Анна» и «Клиент Алексей».

Поддерживаются WAV, MP3, M4A, OGG, OPUS, FLAC, AAC, WMA, MP4, WEBM и MKV со звуком. До **90 минут на файл**. Папки просматриваются без вложенных папок.

## Запустить

На Windows соберите приложение по инструкции ниже, затем запустите `AI Transcriber.exe` из папки сборки. Оставьте рядом папку `_internal` с моделями и библиотеками.

1. Нажмите **«+ Файлы»**, **«Папка»** или перетащите запись в окно.
2. Выберите разбивку, число участников и язык.
3. При необходимости измените папку результатов кнопкой **«Изменить»**.
4. Нажмите **«Расшифровать»** и выберите готовую запись в очереди.
5. Задайте подписи через **«Имена участников»** или нажмите **«Копировать»**.

Имена обновляются в приложении и во всех четырёх файлах результата. Кнопка «Папка» открывает результат записи, включая `transcript.docx`. При сохранении новых имён приложение создаёт DOCX и для прежних результатов со спикерами или каналами. Кнопка **«Остановить»** прерывает текущую обработку; запись можно запустить повторно.

## Всё остаётся у вас

Готовое приложение работает без сетевых запросов. Записи и расшифровки никуда не отправляются. Модели включены в архив; API-ключи, аккаунты и отдельная установка FFmpeg не нужны. Нет телеметрии и автоматической проверки обновлений.

Вычисления выполняются на **процессоре и оперативной памяти компьютера**. Скорость зависит от его мощности и длины записи.

Интернет нужен для скачивания дистрибутива и зависимостей при сборке из исходников. После распаковки готового приложения обработка полностью локальная. Уведомление об этом появляется при первом запуске и доступно в разделе **«О программе»**.

## Точность и проверка

Приложение присваивает голоса внутри одной записи. Имена и роли задаёт человек. Шум, перебивания и короткие реплики могут ухудшать распознавание и разбивку; важные формулировки стоит сверять со звуком.

Модульные проверки охватывают обработку слов, спикеров и экспорт DOCX. [Отчёт о нативной приёмке Ушастика 0.3.1](docs/VERIFICATION.md) относится к исходному выпуску.

## Собрать из исходников

Нужны Python 3.11, зависимости из `requirements.txt` и место для моделей и сборки. `fetch_models.py` загружает зафиксированные модели и сверяет SHA-256 на Windows и macOS. Интернет используется только на этапе подготовки.

**Windows, PowerShell.** Откройте PowerShell в корне проекта. Установите 64-разрядный Python 3.11 с Tcl/Tk и Python Launcher. Проверьте разрядность перед установкой зависимостей.

```powershell
py -3.11-64 -c "import struct, tkinter; assert struct.calcsize('P') == 8; print(tkinter.TkVersion)"
py -3.11-64 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python fetch_models.py
.\.venv\Scripts\python build_windows.py --model model --speakers speaker-model --work .build/windows --dist dist
```

Результат — `dist/AI Transcriber/AI Transcriber.exe`. Если переносите сборку, копируйте всю папку `AI Transcriber` вместе с `_internal` и лицензиями. Для локальной проверки запустите приложение и добавьте `fixtures/диалог 2 голоса.wav`. Выберите режим «По голосам», дождитесь результата и проверьте `transcript.docx` в Word. Для короткой проверки сборки из PowerShell используйте:

```powershell
& '.\dist\AI Transcriber\AI Transcriber.exe'
```

**Mac, Terminal:**

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt -c macos/constraints.txt
python fetch_models.py
python build_macos.py
python test_macos_acceptance.py --app 'dist/AI Transcriber.app' --work acceptance --fixtures fixtures
```

Сборка требует настоящий Mac с macOS 15+, нативный Python 3.11 и Tcl/Tk 8.6. Apple Silicon и Intel собираются отдельно на своей архитектуре. Это две самостоятельные `.app`, без универсального бинарника. В `macos/constraints.txt` зафиксированы совместимые зависимости, включая ONNX Runtime 1.23.2 для Intel. Повторную приёмку запускайте с новой папкой `--work`.

Автоматические тесты:

```bash
python -m unittest test_stitch test_diarization test_engine_boundaries test_docx_export tools.test_package_release
```

При распространении своей сборки сохраняйте лицензии библиотек и моделей; комплект текстов находится в [`licenses/`](licenses), условия перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

Для подготовки публичного архива из готового ZIP используйте `tools/package_release.py`. Он добавляет инструкции и `LICENSES`, сохраняя файлы приложения и подпись Mac:

```bash
python tools/package_release.py --platform macos --input build.zip --output release.zip
```

Для Windows укажите `--platform windows`. Исходный архив и существующие результаты не перезаписываются. Архив исходников медиа-компонентов в текущем релизе соответствует его версиям зависимостей; для новой сборки сверяйте их заново.

## Граница между интерфейсом и обработкой

`app.py` запускает отдельный процесс с флагом `--worker` и путём к JSON-заданию. `engine.run_job` не зависит от Tk. Он читает параметры обработки, обновляет `state.json` и сохраняет результаты. Поэтому другой интерфейс может использовать тот же обработчик.

Для конспектов, краткого содержания, задач и инструкций входом служит `transcript.json` через `engine.read_transcript`. В схеме версии 2 реплики содержат текст, интервалы в секундах и, в соответствующих режимах, идентификаторы говорящих или каналов. Отображаемые имена находятся в `speaker_names`. Будущая постобработка может ссылаться на интервалы исходных реплик и записывать результаты в отдельные файлы рядом с расшифровкой. Распознавание и экспорт уже используют эту схему независимо от будущей постобработки.
